# 04 — Governance, human review and escalation

## Roles
| Role | Who | Responsibility |
|---|---|---|
| Responsible actuary / model owner | Suguru Fujita | All final decisions, sign-off, submissions |
| AI assistant (builder) | Claude | Code, analysis, drafts, proposals — never final decisions |
| AI assistant (challenger) | Separate AI session / sub-agent | Independent critique of code, assumptions, results |

## Human review gates (AI must stop and ask)
| Gate | Decision | Evidence required |
|---|---|---|
| G1 | Target definition & reconstruction | Reconciliation table, toy-case test |
| G2 | Data exclusions / caps / corrections | Data quality log entry, impact on totals |
| G3 | Trend, inflation, development (IBNR) assumptions | Options with low/central/high, sensitivity of D² and totals |
| G4 | Model choice per line | Validation table, diagnostics, explainability check |
| G5 | Kaggle submission | Pre-submission gate checklist (doc 03 §4) |
| G6 | Week 2 adaptation strategy | Market-shift report (doc 05) |

Each gate decision → `logs/decision_log.md` (date, decision, options considered, rationale, evidence link, approver).

## Escalation triggers (stop, flag, discuss)
- Target reconciliation difference > 0.1% of total
- Validation A/E outside 0.9–1.1 for any line
- Model performance drops > 20% (relative D²) between rolling folds
- Any relativity with implausible sign/shape that the data cannot explain
- AI output that could not be verified
- Week 2 data feature with no Week 1 counterpart, or definitional change

## Reproducibility
- `configs/config.yaml`: seeds, paths, assumption values, model hyper-parameters
- `requirements.txt` pinned; Python version noted in README
- One command rebuilds everything: `python -m src.pipeline --market w1`
- Submissions named `outputs/submissions/{market}_{yyyymmdd_hhmm}_{git-short-hash}.csv`; hash logged
- Raw data never modified; processed data regenerated by code; `data/` is git-ignored

## Version control
- Commit early and often; tag milestones: `w1-baseline`, `w1-final`, `w2-final`
- The commit history is evidence of the development path — keep it honest (no squashing of history)

## Model risk / limitations register
Kept in `logs/assumptions_register.md` (assumptions) and the report's Limitations section.
